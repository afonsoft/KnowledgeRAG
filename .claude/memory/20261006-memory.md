# 2026-10-06 Memory

## A2A Agent Card 404 em produção (rag.afonsoft.dev)

- **Sintoma**: `https://rag.afonsoft.dev/.well-known/agent-card.json` → 404.
- **Diagnóstico**: body do 404 era página padrão **nginx** (`<center>nginx</center>`), `cf-cache-status: DYNAMIC` → request passou pelo Cloudflare e morreu no nginx da VM (aaPanel), sem chegar ao Kestrel. App local responde 200 em `http://127.0.0.1:5550/.well-known/agent-card.json`.
- **Causa-raiz**: bloco ACME stock do aaPanel no vhost (`/www/server/panel/vhost/nginx/rag.afonsoft.dev.conf`): `location /.well-known { root /www/wwwroot/rag.afonsoft.dev; }` — prefixo mais específico que `^~ /` (proxy para 5550), servindo `/.well-known/*` do disco → 404. Exatamente o cenário já documentado em `docs/*/INSTALL.md` ("proxy deve repassar /.well-known/*").
- **Fix infra (aplicado)**: `/www/server/panel/vhost/nginx/extension/rag.afonsoft.dev/a2a-agent-card.conf` com `location = /.well-known/agent-card.json` (exact match vence prefixo) → proxy_pass 127.0.0.1:5550. Extension dir sobrevive a edits do painel no conf principal. Backup do vhost em `*.conf.bak.20261006*`. ACME (`acme-challenge`) intacto — segue servido do disco.
- **Segundo defeito encontrado**: card emitia URLs `http://` (endpoint usa `Request.Scheme` puro; sem `UseForwardedHeaders`; CF força https via 301 → POST no http perderia body).
- **Fix código** (branch `feature/devin-20261006-a2a-card-scheme`, commit `485d33c`): `ResolveCardBaseUri` — `A2A:BaseUrl` config > primeiro `X-Forwarded-Proto` > `Request.Scheme`. +2 integration tests (`AgentCard_HonorsForwardedProto`, `AgentCard_BaseUrl_OverridesRequestHost`), 7/7 A2AApiTests verdes.
- **Shim até redeploy da imagem**: `sub_filter "http://$host" "https://$host"` + `sub_filter_types application/json` + `Accept-Encoding ""` no location — card público já serve https:// nas URLs. Remover sub_filter após deploy de imagem com o fix.
- **Lição**: aaPanel insere `location /.well-known` + `if ($uri ~ "^/\.well-known/.*\.(php|...)$") return 403` em todo vhost — sempre auditar esses blocos ao expor endpoints well-known (.json não é bloqueado pelo 403, mas é shadowed pelo location).
